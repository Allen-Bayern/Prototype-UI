# 0.2.0-rc.3 release train 准备记录

日期：2026-07-22

## 背景

`0.2.0-rc.1` 发布后的仓库外人工试用持续暴露 props 撤回、宿主 box model、嵌套 trigger、Dialog 动画、组合面与 component preset 等问题。`0.2.0-rc.2` 只作为收集部分修复的 release notes 草稿存在，没有 V 实体、package 迭代或真实发布；这些改动与后续组合能力统一进入 `0.2.0-rc.3` release train。

## 本次 PR 内完成

- 使用现有 draft `V-PROTO-UI-0003` 开启完整 release train，并继续保持其 `draft` 生命周期。
- 将根 `VERSION`、全部公开 package manifest、内部精确依赖与 launch governance 对齐到 `0.2.0-rc.3`。
- 将自已发布 `0.2.0-rc.1` 以来的 rc.2 草稿修复与 rc.3 组合能力统一写入双语 release notes。
- 生成并评审 `internal/releases/0.2.0-rc.3/package-bom.json`，重新生成 spec agent 投影并运行完整 `release:rehearse`。

## 合并后的发布边界

1. 本 PR 只准备发行身份与物料，不执行 npm 发布，不创建 `v0.2.0-rc.3` tag，也不把 `V-PROTO-UI-0003` 转为 `active`。
2. PR 合入 `main` 后，从合入 commit 手动运行 `Release Packages` workflow，选择 `mode=publish-all`、`profile=workspace` 与 `resume_published=false`。
3. workflow 必须先发布全部公开 package，之后才能创建 tag、GitHub prerelease 与不可变 spec snapshot。
4. 核对 npm、dist-tag、tag、GitHub Release 与 snapshot digest 后，从最新 `main` 建立独立证据分支，回填 `publishedAt`、`commit`、`specSnapshotDigest` 并激活 V 实体。
5. 面向用户的仓库 README、官网试用命令与当前版本说明在证据 PR 前继续指向已发布的 `0.2.0-rc.1`；随 rc.3 tarball 分发的 CLI README 则预先固定到自身版本。

本记录描述的是发布准备，不是发布完成证据。
