# 2026-07-20 0.2 RC 公开事实与第三方声明收口记录

> Internal record. Not normative. 本文记录 `v0.2.0-rc.0` 真实发布前，对官网公开事实、源码链接和外部来源原型包发行内容的一次收口。版本与发布约束仍以 V 实体、`D-GLOBAL-RELEASE-VERSION-0001` 和 release governance 文档为准；本文也不替代上游许可证或法律意见。

## 1）背景

完整 release rehearsal 已经能够验证 37 个公开 package、隔离 consumer、spec snapshot 与官网构建，但构建成功不等于公开信息和发行归属已经正确。复查 2026-07-18 与 2026-07-20 的近期 records 后，仍发现：

- 官网 Status 保留已经过去的 2026-05-14 launch 目标。
- Header 的 Prototypes 链接指向不存在的旧路由，GitHub social link 仍指向 Starlight 仓库。
- 部分公开文档把维护者本机绝对路径作为源码链接。
- Lucide README 声明保留上游 Lucide / Feather notice，但 npm staging 只复制 Proto UI 根 MIT `LICENSE`；Shadcn package 也没有把固定比较基线的上游 MIT notice 作为独立发行物。

因此，“阶段 A 只剩真实发布”只适用于发行机械；在触发真实 publish 前，还需要让公开事实与 tarball 内容满足既有治理声明。

## 2）本轮决定

1. 官网 Status 不再承诺已经过去的发布日期，改为描述当前 0.2 收口状态，以及稳定 Quick Start 跟随 `latest`、RC Trial 固定精确候选版本的边界。
2. Header 的 Prototypes 入口改为现有 `ui-libraries` 路由，GitHub social link 改为 Proto UI 仓库。
3. 官网中的本机绝对源码链接改为公开 GitHub `blob` / `tree` 链接。
4. 外部来源原型包采用 package-local `THIRD_PARTY_NOTICES.md`。Lucide 包分发 `lucide-static@1.8.0` 的 ISC 与 Feather-derived MIT notice；Shadcn 包分发固定上游比较基线的 MIT notice 和非官方状态说明。
5. package manifest 通过 `protoUi.release.thirdPartyNotices` 明确声明需要进入 tarball 的 notice；release staging 自动复制声明文件并加入 published `files`。
6. release assets check 固定检查当前 Lucide 与 Shadcn package 的声明文件及关键 attribution，release script unit test 验证声明文件实际进入 staged tarball。

package-local notice 是当前最小且可审计的发行单元：直接消费某一个 tarball 的用户无需回到 monorepo 查找总表，未来新增外部原型库也可以复用同一声明机制。本决定只处理发行携带方式，不主张 Proto UI 拥有上游图形、设计、名称、商标或源码。

## 3）验证边界

本轮完成后应至少验证：

- `release:assets:check` 能在 notice 缺失或关键 attribution 被删除时失败。
- release unit tests 能证明声明的 notice 同时进入 staged manifest 和目录。
- Lucide 与 Shadcn 的 `npm publish --dry-run` 文件列表包含 `THIRD_PARTY_NOTICES.md`。
- 官网不再包含维护者本机绝对路径，修正后的导航和中英文 Status 可以完成 production build。
- 完整 `release:rehearse` 继续通过，且不创建 tag、GitHub Release 或 npm 版本。

## 4）后续边界

- 本轮不顺带补齐全部占位页、组件 API 表、搜索与 code block 视觉样式；这些仍属于后续文档投射与内容补全。
- 本轮不把 Geist build-time warning 或固定 bundle kB 阈值提升为 RC blocker。
- 第三方来源的结构化 provenance / upstream revision schema 仍可在更多外部原型库出现后单独设计；当前 package-local notice 不替代 P 实体与 record 中的来源追溯。
- 真实发布后仍需核对 npm、dist-tag、Git tag、GitHub Release、BOM 与 spec snapshot，并以独立证据 PR 将 V 实体从 `draft` 提升为 `active`。
