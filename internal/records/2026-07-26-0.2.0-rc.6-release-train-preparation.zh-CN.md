# 0.2.0-rc.6 release train 准备记录

日期：2026-07-26

## 背景

`0.2.0-rc.5` 发布后的 demo-matrix 人工试用继续暴露 Shadcn Switch 几何与 focus ring、Shadcn Dialog 透明 Trigger/Close 组合、跨 adapter focus-visible 与焦点归还等原型质量问题。对应修复已经通过 Web Component、React 与 Vue 的共享 DOM journey 验收；component preset authoring 也从 CLI 手写配置收敛为 prototype library 内与组件目录共置的独立 recipe。本轮据此开启 `0.2.0-rc.6` 全局精确 release train。

## 本次准备范围

- 新增 draft `V-PROTO-UI-0006`，声明 `0.2.0-rc.6`、`v0.2.0-rc.6` 与 npm `next` channel。
- 将根 `VERSION`、全部公开 package manifest、内部精确依赖与 launch governance 对齐到 `0.2.0-rc.6`。
- 将 Switch 视觉修正、Dialog 跨 adapter 交互修复、component-local preset authoring 与共享 Web conformance journey 写入双语 release notes。
- 将 rc.5 发布后才合入的 catalog revision 与新测试实体准确归入 `0.2.0-rc.6`。
- 生成并评审 `internal/releases/0.2.0-rc.6/package-bom.json`，重新生成 spec agent 投影并运行完整 `release:rehearse`。

## 合并后的发布边界

1. 本准备分支只建立发行身份与物料，不执行 npm 发布，不创建 `v0.2.0-rc.6` tag，也不把 `V-PROTO-UI-0006` 转为 `active`。
2. 准备 PR 合入 `main` 后，从合入 commit 手动运行 `Release Packages` workflow，选择 `mode=publish-all`、`profile=workspace` 与 `resume_published=false`。
3. workflow 必须先发布全部公开 package，之后才能创建 tag、GitHub prerelease 与不可变 spec snapshot。
4. 核对 npm、dist-tag、tag、GitHub Release 与 snapshot digest 后，从最新 `main` 建立独立证据分支，回填 `publishedAt`、`commit`、`specSnapshotDigest` 并激活 V 实体。
5. 面向用户的仓库 README、官网试用命令与当前版本说明在证据 PR 前继续指向已发布的 `0.2.0-rc.5`；随 rc.6 tarball 分发的 CLI README 则预先固定到自身版本。

本记录描述的是发布准备，不是发布完成证据。
