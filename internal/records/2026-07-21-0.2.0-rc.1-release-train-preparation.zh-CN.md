# 0.2.0-rc.1 release train 准备记录

日期：2026-07-21

## 背景

`0.2.0-rc.0` 外部人工试用暴露出两类需要在下一候选版本处理的问题：默认 Web 主题没有在缺少显式标记时跟随系统偏好，以及 Adapter 生成的宿主组件丢失 Prototype 公共类型。本次变更把两项修正与 `0.2.0-rc.1` 发布准备放在同一个受评审的 release train 中。

## 本次 PR 内完成

- 新增 draft `V-PROTO-UI-0002`，声明 `0.2.0-rc.1` 的全局发行身份。
- 将根 `VERSION`、全部公开 package manifest、内部精确依赖与 launch governance 对齐到 `0.2.0-rc.1`。
- 生成并评审 `internal/releases/0.2.0-rc.1/package-bom.json` 与双语 release notes。
- 运行完整 `release:rehearse`，覆盖 spec、类型、测试、打包、React consumer、CLI 多宿主 consumer 与文档构建，但不进行发布。

## 合并后的发布边界

1. PR 合入 `main` 后，手动运行 `Release Packages` workflow，选择 `mode=publish-all` 与 `profile=workspace`。
2. workflow 通过 npm Trusted Publishing 发布全部公开 package，并在全部发布成功后创建 `v0.2.0-rc.1` tag、GitHub prerelease 与不可变 spec snapshot。
3. 核对 npm、tag、GitHub release 与 snapshot digest 后，通过后续证据 PR 填写 `publishedAt`、`commit`、`specSnapshotDigest`，并将 `V-PROTO-UI-0002` 从 `draft` 转为 `active`。
4. 面向用户的安装文档在真实发布前继续指向已存在的 `0.2.0-rc.0`；发布证据 PR 再把它们切换到 `0.2.0-rc.1`。随 rc.1 tarball 一起分发的 CLI README 则预先固定为自身版本。

本记录描述的是一次发布准备，不是发布完成证据。
